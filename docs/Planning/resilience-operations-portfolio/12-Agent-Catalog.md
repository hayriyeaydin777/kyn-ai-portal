# 12. Agent Catalog
## Purpose
Provide discoverability and governance for reusable agent configurations.
## Agent metadata
Name, purpose, owner, lifecycle, version, provider policy, input/output schemas, allowlisted tools, security tier, approval requirement, prompt version, evaluation status, observability signals.
## Lifecycle
Draft -> Evaluation -> Review -> Approved -> Deprecated -> Retired.
## Initial agents
Modernization, Architecture, Code Review, Testing, Evidence, Dependency, Briefing.
## Rules
Catalog entries are metadata over a shared runtime. Promotion requires evaluation thresholds and approval. Tool permissions are deny-by-default. Version history is immutable.
